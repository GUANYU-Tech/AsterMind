# Goal 模板

这是 Midlayer 独立 worker Goal 的唯一统一模板。Writer 将 `# Goal:` 起的正文复制为分配的 worktree 根目录的 `GOAL.md`，保留通用章节和完成语义、填写占位内容；只读 Goal 可在任务消息中承载相同内容，不为模板修改共享 checkout 或额外创建 worktree。可增加任务特有小节，不维护第二份模板。仓库通用约束以根 `AGENTS.md` 为准，此处只写必要的权限提醒、任务特有版本、路径、资源状态和例外。短小只读咨询无需建立独立 Goal，直接说明问题、范围和输出即可。

## Hard acceptance gates

下列 gate 是完成条件，不是参考目标。诊断或探索任务可以把“形成经验证的结论、排除指定假设、交付可复现实验”作为 gate，不得为了形式强填无意义的数值。若 gate 接受“实现成功”或“以指定证据证明不可行”等多个合法结果，必须在开工前把各分支及其证据写清，不能失败后临时降低完成标准。“争取达到”“越快越好”等 stretch target 必须单独标明，不能与 hard gate 混写。

每项 gate 写明证据取得方式，现有工具不能产出时说明如何取得。精度/速度阈值可以验收结果，但不能授权以 production duration 或误差调参；目标不能直接指定某个可调偏移量，必要时改为来源、覆盖、趋势或结构不变量验收。核实指标、case、路径和分支；推断须标明并允许推翻，失败先例不限定解法，零拟合、owner 与跨硬件共享模型等结果边界仍须写清。

## Complete、Checkpoint 与 Blocked

- Completed：全部 hard acceptance gates 有最终证据证明 Pass；或者用户明确豁免仍为 Fail 的 gate 并要求停止。除此之外不得声称完成。
- Checkpoint：代码提交、测试通过、报告/工具修复、部分指标改善、阶段结论、运行时限耗尽、unsupported 或 WONTFIX 单独出现时都只能是 checkpoint。存在未获豁免的 Fail 时明确写“Goal 未完成”，继续任务范围内可行动的高优先级问题；满足下述阻塞条件则报告 blocked，不能将普通 checkpoint 作为等待用户再次催促的理由。
- WONTFIX/unsupported：对 hard gates 内拟放弃的具体子问题，给出边界明确的证据、已否定候选和无法合法继续的原因；“缺少证据”本身意味着在任务范围和预算内继续分析、受限验证或换方向，不能批量把主要目标标成 WONTFIX。诊断型 gate 只有事先将“证明不支持或无法合法修复”列为合法结果，且证据齐全时才可据此 Pass。范围外能力和已约定近似说明限制即可，不因此扩大任务。
- Blocked：仅当本任务范围和预算内剩余有效路径都需要新增授权或遭遇无法绕开的外部阻塞时使用；列出阻塞、已推进路径和解除条件，不扩大范围穷举所有可能，且状态仍不是 completed。
