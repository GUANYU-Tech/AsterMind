# Orbit Trace Contract

## Status

- Contract ID: `orbitserve.orbit_trace_contract.v2-draft`
- Decision status: frozen for Phase 0 implementation planning
- Frozen date: 2026-07-20
- Code status: Phase 1 canonical type names and compatibility aliases are
  implemented; Phase 2 provides opt-in Orbit Trace v2 geometry-only writing
  and reading; the existing writer remains the default

This document freezes module ownership and deterministic output requirements.
It does not change the current simulator or trace files by itself.

The separately frozen
[`SGP4_INPUT_CONTRACT.md`](SGP4_INPUT_CONTRACT.md) defines the future
full-precision SGP4 mean-element input boundary. That contract is additive: it
does not change this Orbit Trace v2 output contract, the current circular
two-body propagation path, or the default writer.

## Confirmed decisions

1. `OrbitTraceManifest` and `OrbitTraceBundle` are the canonical future public
   type names.
2. `RuntimeTraceManifest` and `RuntimeTraceBundle` remain temporary compatibility
   aliases referring to the same class objects as the canonical types.
3. `satellite_initial_soc`, `terminal_catalog`, and
   `active_graph_snapshots` are Runtime-owned and must be removed from new Orbit
   outputs.
4. Identical canonical inputs must produce byte-for-byte identical trace files.

Type-name compatibility is distinct from legacy trace-file compatibility. Phase
0 guarantees the future aliases but does not yet set a removal version for old
v1 files or names.

## Module boundary

Orbit is a deterministic producer of physical geometry and environmental facts.
It does not make communication or request-execution decisions.

### Orbit-owned inputs

- constellation and stable satellite identity inputs;
- orbital parameters, epoch, duration, and sample grid;
- ground ingress identity and coordinates;
- geometric visibility and propagation model parameters;
- sunlight and shadow model parameters;
- schema and algorithm versions that affect generated bytes.

An output directory, absolute path, host name, process ID, wall-clock generation
time, or temporary-file name is not a physical input and must not affect trace
identity or file bytes.

### Orbit-owned outputs

- trace metadata, relative file references, hashes, provenance, and warnings;
- a stable satellite catalog containing only geometry/topology identity needed
  to interpret the trace;
- monotonically ordered ephemeris samples in one declared coordinate frame;
- SGL geometric visibility windows and propagation distance or delay;
- ISL geometric visibility windows and propagation distance or delay;
- sunlight and shadow windows or samples.

Orbit may describe whether two endpoints are geometrically visible. It must not
describe whether Runtime selected, reserved, queued, or activated that link.

### Runtime-owned derived state

| Field or concept | Runtime source of truth |
|---|---|
| `satellite_initial_soc` | Runtime configuration, constrained by the Architecture energy profile |
| `terminal_catalog` | Orbit satellite identities plus Architecture terminal capabilities and Runtime configuration |
| `active_graph_snapshots` | Orbit visibility plus Architecture capabilities, Runtime terminal state, and Runtime policy |
| link bandwidth and capacity | Architecture plus Runtime configuration |
| terminal occupancy and allocation | Runtime state |
| route, queue, and congestion state | Runtime state and scheduler |
| DVFS and current/post-request SOC | Runtime energy state |

The three named legacy fields must not appear in new Orbit v2 payloads, in
`OrbitTraceBundle`, or in Orbit-generated files.

## Canonical public types

Phase 1 establishes this identity relationship:

```python
RuntimeTraceManifest = OrbitTraceManifest
RuntimeTraceBundle = OrbitTraceBundle
SurrogateTraceBundle = OrbitTraceBundle
```

The aliases must be object-identical, not subclasses or duplicate dataclasses.
During the compatibility period, `orbitserve.orbit` exports both canonical and
legacy names. New Orbit code and documentation use `OrbitTrace*`; existing
consumers may migrate independently while aliases remain available.

## Orbit Trace v2 semantic contract

### Manifest invariants

The manifest must contain or resolve:

- a schema version and trace model;
- a stable `trace_id` derived from canonical physical inputs and algorithm
  versions, never the output directory;
- evaluated status, scope, and formal-experiment eligibility;
- epoch, start, end, duration, and step semantics;
- relative POSIX-style file paths;
- SHA-256 values for emitted data-file bytes;
- deterministic provenance and warning fields.

If a manifest content hash is stored in the manifest, it is calculated from a
canonical manifest representation with that self-hash field omitted. A field
must not claim to be the SHA-256 of final bytes that contain the field itself.

### Bundle invariants

- `trace_id`, schema, time range, and satellite identities agree with the
  manifest and every trace file.
- Every `satellite_id` is unique and stable for the same canonical input.
- Ephemeris records are ordered by `(time_s, satellite_id)` and sample times are
  monotonic.
- SGL windows use the same `ingress_id` namespace as canonical Workload input.
- Visibility windows use half-open intervals `[start_s, end_s)` with
  `start_s < end_s`.
- ISL endpoint ordering is canonical; an undirected pair cannot change identity
  when its construction order changes.
- Orbit output contains geometry and propagation facts only.

## Byte-level reproducibility contract

Byte reproducibility applies when canonical inputs, code version, schema
version, and declared algorithm version are identical.

### Canonical ordering

| Output | Required primary ordering |
|---|---|
| satellite catalog | `satellite_id` |
| ephemeris samples | `time_s`, `satellite_id` |
| SGL windows | `start_s`, `ingress_id`, `satellite_id`, `end_s` |
| ISL windows | `start_s`, canonical endpoint A, canonical endpoint B, `end_s` |
| sunlight/shadow windows | `satellite_id`, `start_s`, `end_s` |

All set-like arrays, identifiers, warning collections, and provenance lists must
have an explicit deterministic ordering and deterministic de-duplication rule.

### Canonical serialization

- UTF-8 without a byte-order mark;
- LF (`\n`) line endings on every supported platform;
- exactly one final newline per text file;
- lexicographically sorted JSON object keys;
- one canonical JSON object per JSONL line;
- stable relative paths using `/` separators;
- finite numeric values only: no NaN or Infinity;
- one documented float normalization rule, including negative zero and time
  boundary precision;
- no non-deterministic timestamps or host-specific metadata.

Phase 2 uses `orbitserve.orbit.write_orbit_trace_v2` and
`orbitserve.orbit.load_orbit_trace_v2`. The writer emits
`trace_manifest.json`, `satellite_catalog.json`, `ephemeris_trace.json`,
`sgl_windows.json`, `isl_windows.json`, and `sunlight_windows.json`. Every data
file is a JSON object carrying the schema, trace ID, data kind, and canonical
record array.

All time and boundary values are rounded to nine decimal places. Other finite
floating-point values are normalized to 15 significant decimal digits.
Negative zero is serialized as `0.0`. JSON is UTF-8 without BOM, uses sorted
keys and compact separators, and ends with exactly one LF byte. The manifest
field `trace_manifest_content_sha256` hashes the canonical manifest with that
self-hash field omitted.

The Phase 2 writer is explicit and fail-closed: it rejects Runtime- or
Architecture-owned capacity, terminal, SOC, active-graph, routing, queue,
congestion, DVFS, and energy-accounting fields. It never stores the output
directory, host name, working directory, or generation timestamp.

### Required reproducibility checks

Future implementation tests must generate the same input:

1. into two different output directories;
2. from mappings with different insertion order;
3. in independent Python processes with different `PYTHONHASHSEED` values;
4. on supported Windows and CI Linux environments.

The file set, every file's raw bytes, every SHA-256, and `trace_id` must match.

## Compatibility and migration order

The migration must keep the integration branch runnable:

1. introduce canonical `OrbitTrace*` types with legacy symbol aliases and no
   behavior change;
2. add v2 pure-geometry writing and reading without making it the default;
3. let Runtime derive initial SOC, terminal catalogs, and active graphs;
4. add any approved legacy-v1 file adapter on the Runtime side;
5. switch the default Orbit writer to v2;
6. migrate DSE, baseline, integration, smoke, and slow consumers;
7. set legacy removal versions only after all consumers have migrated.

## Ownership and change control

- The Orbit owner changes `src/orbitserve/orbit/` and Orbit unit tests.
- The Runtime owner changes Runtime derivation, compatibility adapters, and
  Runtime tests.
- `ingress_id` changes require agreement between Orbit and Workload owners.
- Public field additions, removals, or semantic changes require agreement
  between the producing and consuming module owners before code or interface
  tests change.
- Full Runtime or DSE path changes require relevant slow tests after unit,
  integration, and smoke tests pass.

## Phase 0 acceptance criteria

- The three confirmed decisions are written as one authoritative repository
  contract.
- Ownership of every migrated field is explicit.
- Deterministic identity, ordering, serialization, and hashing rules are
  explicit.
- Compatibility aliases and migration sequence are explicit.
- No runtime behavior or public Python symbol has changed in Phase 0.
