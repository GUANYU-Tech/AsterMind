## 验收结果

- Ubuntu / WSL 主配置矩阵与兼容测试 19 项全部通过。
- 扩展回归共 135 项，132 项通过。三个 ISLSim 差异已在原版复现。
- 路由与通信的额外基线检查共 17 项，其中 8 项失败，失败与应用配置改动前一致。

## 复现

在仓库根目录安装项目依赖并构建原生工具后运行下列命令。主矩阵执行配置加载和模块装配，计算计划检查使用 `with_scheduler=False`。

```bash
python -m astermind.common.build_native
python -m unittest -v tests.unit.test_configuration_matrix tests.unit.test_offline_scenario_config tests.unit.test_builder_config_compatibility
```

## 当前限制

- `earliest_arrival` 尚未注册到统一路由。离线入口会拒绝该值。
- 离线入口接收预先算好的调度和到达时间。实时外部 Scheduler、上一轮结束触发下一轮、按实时 KV 命中决定补传仍需运行时支持。SLO 用于配置校验，尚未作为运行时调度输入。
- 显存预算文件必须绑定实际硬件、模型和部署参数。随库的 H200／Qwen3-4B 预算示例与当前硬件文件指纹不同。通过的自定义预算用例是明确标为假设的合成数据。
- 扩展运行中的三个 ISLSim 失败在原版 `a5a9c73` 上也出现。它们涉及原生默认配置与 AsterMind 字段不完全匹配、整份原生配置作为覆盖项的回读，以及固定调制结果。兼容副本的容量、可行性与预计算用例通过。
- 另有八个旧路由／通信行为断言在原版重复失败。主矩阵确认配置和注册的选择器进入模块，运行时选路原有差异见基线日志。

- Windows 原生硬件加载器在 C500 和 910B 的参考路径校验上失败。这两种硬件和其余 GPU 已在 WSL 中通过装配验收。
