# OrbitServe 固定设计仿真

当前唯一仿真配置对象是 `SimulationConfig`。一次运行输入一套确定配置，
使用全局选择的 Midlayer/Roofline 和原生 vLLM Scheduler 计算，输出请求、时间、通信与 KV 迁移指标。
旧 Analytical 性能表、插值计算、能源/SOC/DVFS 执行链及 DSE 已删除。

```bash
python -m astermind.experiments.cli examples/native/two_cells.json --out results/cells/basic.json --full
```

`--full` 输出完整 JSON；默认输出摘要及 `*.artifacts/native_result.json`。
`--artifact-dir` 指定审计与物理数据目录。`python -m astermind` 与标准实验 CLI
使用同一 Native Simulator。

`physical` 描述设备连接，`cells` 描述模型、硬件、rank 放置和计算配置，
`requests` 描述请求，`migrations` 描述迁移；计算严格按这些配置执行。
轨道与链路预算只通过 `physical_network` 或 `physical_dataset` 输入，两者互斥。
显式数据集必须完整且通过哈希校验；`runtime_network` 保留现有故障与恢复配置。

`orbit`、`link_parameters` 已从配置模型删除，包含空值的旧字段也会报错。
数字 schema `1` 和字符串 `orbitserve.native_cells.v1` 均使用统一 Comm。
全局 `compute_mode` 选择 `midlayer` 或 `roofline`；`communication` 配置通信策略、
协议容量口径、重试和超时。旧 backend/timeline_mode/communication_mode 输入已删除。
新增模式输出完整原始报告，`viz/` 未修改，暂不展示新增模式。

依赖、设备资源和审计参见 [Native 使用说明](../astermind/README.md)；
数据预计算参见 [物理数据说明](../astermind/experiments/PHYSICAL_DATA.md)。
独立 workload 工具保留，用于请求数据准备与校验；Native 仍直接读取 SimulationConfig.requests。
